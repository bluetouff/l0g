Pour comprendre la concurrence dans le cloud, les enquêteurs britanniques ont posé une question inhabituelle : combien coûteraient les logiciels utilisés par les clients d’Azure si Microsoft devait les payer aux conditions qu’il applique à Amazon ou à Google ? Ils ont pris les usages observés, appliqué les prix prévus dans les contrats des concurrents, puis comparé ce coût théorique aux dépenses de licences des clients d’Azure. Ce calcul figure dans le rapport final de la Competition and Markets Authority, la CMA, publié le 31 juillet 2025. <sup><a href="#source-1">[1]</a></sup> <sup><a href="#source-8">[8]</a></sup>

L’exercice révèle la particularité de Microsoft : l’entreprise vend à la fois des logiciels nécessaires à certains services cloud et son propre hébergement, Azure. Amazon et Google peuvent donc être ses concurrents pour accueillir une application et ses clients pour obtenir les droits sur les logiciels qui la font fonctionner. La CMA conclut que les pratiques de licence de Microsoft affaiblissent leur capacité à rivaliser pour ces usages. Microsoft conteste cette conclusion. <sup><a href="#source-1">[1]</a></sup> <sup><a href="#source-14">[14]</a></sup>

Pour une administration, cette double position a une conséquence très concrète. Un logiciel choisi plusieurs années auparavant peut continuer à orienter le choix d’un hébergeur. Après les [dépendances opérationnelles](/posts/quitter-microsoft-1-etat-dependances/) et les [contrats qui les installent](/posts/quitter-microsoft-2-contrats-choix-installation/), ce troisième volet suit les droits d’usage jusque dans le centre de données. Les changements intervenus en 2026 font partie de l’enquête : plusieurs portes ont été ouvertes, chacune avec son périmètre.

## Le logiciel voyage avec des conditions

Prenons un exemple pédagogique : une application de gestion administrative utilise une base de données SQL Server, installée dans une machine virtuelle Windows Server. SQL Server organise les données ; Windows Server est le système d’exploitation sur lequel il fonctionne dans cet exemple. La machine virtuelle fournit à ce système un ordinateur défini par logiciel, hébergé sur un serveur physique. La CMA examine précisément cette superposition dans son analyse des licences. <sup><a href="#source-8">[8]</a></sup>

L’équipe informatique souhaite déplacer cette application. Elle doit vérifier que le service pourra fonctionner à destination, avec ses données, ses accès et ses raccordements. Elle doit aussi établir le droit d’y exécuter chaque logiciel. Les conditions universelles de Microsoft rendent le client responsable du respect de son accord de licence, quel que soit l’emplacement du matériel. Elles encadrent spécifiquement l’utilisation de machines gérées par un tiers. <sup><a href="#source-2">[2]</a></sup>

La formule *Bring Your Own Licence*, ou BYOL, désigne l’utilisation chez un hébergeur de licences déjà détenues par le client. Elle recouvre plusieurs mécanismes. Leur accès dépend notamment du produit et de la couverture souscrite. La **Software Assurance** est une couverture associée à la licence, qui donne accès à de nouvelles versions et à des droits supplémentaires pendant sa durée. Certains abonnements procurent des droits équivalents. Une licence perpétuelle peut continuer à autoriser son usage de base après la fin de cette couverture, tandis que les avantages attachés à la couverture active expirent selon leurs conditions. <sup><a href="#source-4">[4]</a></sup> <sup><a href="#source-6">[6]</a></sup>

Cette distinction explique pourquoi la phrase « nous avons déjà acheté le logiciel » laisse encore du travail à l’acheteur. Il faut retrouver la version, le type de licence et les droits qui restent actifs, puis les rapprocher du service envisagé. Le budget déjà consacré au logiciel et la possibilité de le déployer ailleurs sont deux informations complémentaires.

## Trois destinations pour la même application

Sur Azure, l’**Azure Hybrid Benefit** permet de valoriser des licences Windows Server ou SQL Server éligibles, avec abonnement ou Software Assurance actifs. Pour Windows Server sur une machine virtuelle Azure, Microsoft décrit un bénéfice portant sur la composante licence Windows : les ressources de calcul continuent d’être facturées. Les conditions et quantités nécessaires varient selon le produit et le service. Le droit existant contribue ainsi à rendre Azure économiquement intéressant pour un client déjà équipé. <sup><a href="#source-7">[7]</a></sup>

Une autre voie existe chez un *Authorized Outsourcer*, catégorie que Microsoft définit dans ses conditions. Depuis octobre 2022, le **Flexible Virtualization Benefit** permet d’y utiliser des logiciels éligibles sur des serveurs dédiés ou partagés, avec abonnement ou Software Assurance actifs. Windows Server entre dans ce dispositif. Les obligations de licence du produit restent applicables, notamment celles qui concernent les ressources couvertes et les accès. <sup><a href="#source-2">[2]</a></sup> <sup><a href="#source-4">[4]</a></sup>

La définition de l’hébergeur est décisive. Un Authorized Outsourcer doit être extérieur à la catégorie des *Listed Providers* et ne pas utiliser l’un d’eux comme fournisseur de centre de données pour ce service. La liste publiée par Microsoft comprend Alibaba, Amazon, Google et Microsoft lui-même. Un intermédiaire européen hébergeant le service sur l’infrastructure d’un de ces acteurs ne devient donc pas éligible à ce dispositif par sa seule adresse européenne. Azure dispose de ses droits propres, dont l’Azure Hybrid Benefit. <sup><a href="#source-3">[3]</a></sup> <sup><a href="#source-7">[7]</a></sup>

Chez AWS ou Google, il faut encore distinguer les deux couches de notre application. SQL Server peut relever de **License Mobility through Software Assurance**, un droit de déploiement auprès d’un partenaire qualifié, sous les conditions du produit et avec vérification des licences. La documentation Microsoft précise que le système d’exploitation Windows Server est exclu de ce mécanisme et doit être fourni par le partenaire choisi. Dans cet exemple sur matériel partagé, le client peut donc apporter sa licence SQL éligible tout en achetant un service incluant Windows auprès de l’hébergeur. <sup><a href="#source-5">[5]</a></sup> <sup><a href="#source-8">[8]</a></sup>

La date d’acquisition compte aussi. Les modifications annoncées en 2019 ont conservé certaines possibilités sur matériel dédié chez les Listed Providers pour les licences acquises avant le 1er octobre 2019 et les versions déjà disponibles. Passer à une version publiée à compter du 1er octobre 2019 relève des nouvelles conditions. Cette exception mérite un examen du contrat et de l’historique du parc ; la généraliser aux nouvelles versions donnerait une fausse carte des possibilités. <sup><a href="#source-18">[18]</a></sup>

Une annonce d’avril 2026 appelle la même précision. Microsoft a étendu des droits équivalents à la Software Assurance aux abonnements Windows Server et SQL Server achetés par le canal CSP sous Microsoft Customer Agreement. Les licences perpétuelles de ce canal restent inchangées. Le mot « mobilité » couvre toutefois plusieurs droits : les Product Terms distinguent la réaffectation entre serveurs d’une même ferme et le déploiement d’applications chez un partenaire. Le tableau Windows Server réserve toujours la ligne *License Mobility* à l’External Connector, un droit d’accès distinct de la licence du système d’exploitation. Le guide de mobilité continue d’exclure ce dernier. L’annonce d’avril doit donc être lue avec ces conditions propres à chaque produit. <sup><a href="#source-9">[9]</a></sup> <sup><a href="#source-6">[6]</a></sup> <sup><a href="#source-5">[5]</a></sup>

## Le concurrent achète une partie de son offre à Microsoft

Revenons au calcul britannique. Un hébergeur qui fournit Windows Server dans son service acquiert les droits nécessaires auprès de Microsoft, notamment à travers un contrat SPLA, pour *Services Provider License Agreement*. Cette licence devient un coût dans la fabrication de son offre. Microsoft fixe ainsi les conditions d’un composant utilisé par un concurrent, tout en vendant au client final une offre Azure qui utilise ce composant. <sup><a href="#source-1">[1]</a></sup> <sup><a href="#source-8">[8]</a></sup>

Pour examiner cette relation, la CMA a exploité des données de clients Azure britanniques en 2024. L’unité utilisée, l’heure-cœur virtuel, combine la durée d’exécution et le nombre de cœurs de processeur virtuels mobilisés. Elle a calculé les coûts de licence qu’entraînerait leur consommation aux conditions SPLA d’AWS et de Google, en ajustant les données pour les différences de facturation et d’utilisation. Dans sa comparaison avec les dépenses de licence sur Azure, elle a retenu les usages Windows Server bénéficiant d’Azure Hybrid Benefit et les usages SQL Server payés à la consommation. SQL apporté par le client suit un autre chemin, ce qui explique son exclusion de cette seconde catégorie. Les services SQL entièrement gérés sont également hors de ce calcul. <sup><a href="#source-8">[8]</a></sup>

Le résultat important tient au niveau auquel apparaît l’écart. La CMA constate que, pour certains produits et clients, le prix demandé aux concurrents pour obtenir le logiciel peut dépasser le prix de licence facturé aux clients d’Azure. Elle estime que les concurrents répercutent au moins une partie de ces coûts et que les pratiques de Microsoft réduisent la concurrence dans les marchés britanniques du cloud. <sup><a href="#source-1">[1]</a></sup>

Le rapport contient aussi une limite essentielle pour l’acheteur. Sur les instances payées à la consommation sélectionnées par Microsoft, les prix catalogue d’AWS étaient égaux ou inférieurs à ceux d’Azure. La CMA rattache cette comparaison à la situation d’un client sans licence préexistante éligible à l’Azure Hybrid Benefit. **Le parc de licences du client peut changer le résultat de la comparaison.** Il faut donc rapprocher les offres d’un même besoin et d’une même situation de départ. <sup><a href="#source-1">[1]</a></sup>

Microsoft oppose une autre lecture dans sa réponse du 4 juin 2026. L’entreprise invoque la croissance de ses concurrents, les transformations liées à l’IA et le poids qu’elle juge faible de ses redevances dans leurs activités. Elle défend des prix différents selon l’étendue des droits accordés et conteste qu’une intervention réglementaire améliorerait les résultats pour les clients. Ce sont les arguments du fournisseur, versés à la nouvelle procédure britannique. <sup><a href="#source-14">[14]</a></sup>

Les conditions détaillées des contrats SPLA et les écarts précis sont masqués dans l’enquête publique. Calculer un surcoût pour un client donné exige donc ses propres offres et son parc de licences. Le rapport explique pourquoi deux hébergeurs disposant d’infrastructures performantes peuvent présenter des offres différentes à un client qui souhaite garder les mêmes logiciels. Une partie des conditions commerciales se forme chez leur fournisseur commun. <sup><a href="#source-8">[8]</a></sup>

## Ce que les hébergeurs européens ont obtenu

Le paysage a évolué depuis les premières plaintes. Le 18 juillet 2025, CISPE, association de fournisseurs d’infrastructure cloud, annonce un accord permettant à ses membres qualifiés de proposer notamment Windows Server et SQL Server à la consommation via le programme CSP-Hoster. L’association décrit des conditions tarifaires comparables à celles d’Azure et la possibilité d’héberger ces usages sans transmettre les coordonnées des clients à Microsoft. Ces avantages s’ajoutent au Flexible Virtualization Benefit. <sup><a href="#source-10">[10]</a></sup>

Le périmètre annoncé comprend les membres existants et les fournisseurs européens éligibles rejoignant CISPE dans les mois suivants. Les Listed Providers en sont exclus. Le communiqué prévoit une revue après la première année, avec une éventuelle extension de l’accès. Les documents consultés ne permettent pas d’en déduire une ouverture automatique à tous les hébergeurs en 2026. <sup><a href="#source-10">[10]</a></sup>

En septembre 2026, le quatrième rapport de l’European Cloud Competition Observatory, ECCO, maintient Microsoft au niveau vert de son suivi. Il fait état d’une coopération pour mettre en œuvre les engagements finalisés en juillet 2025 et salue une modification des prix des mises à jour de sécurité prolongées. ECCO rassemble des membres de CISPE, avec des organisations clientes comme observateurs, sous l’égide de l’association. Son appréciation documente le suivi de leur accord ; elle reste distincte d’une décision d’autorité de concurrence. <sup><a href="#source-11">[11]</a></sup>

Cette évolution compte pour la souveraineté européenne. Pouvoir proposer les logiciels utilisés par leurs clients dans de meilleures conditions donne aux hébergeurs concernés une voie pour accueillir ces applications sur leurs propres infrastructures. Cela laisse subsister une relation avec l’éditeur : les produits disponibles, les droits et les programmes restent définis dans les accords Microsoft. Le progrès sur le choix d’infrastructure et la dépendance au logiciel doivent être appréciés ensemble.

## Une mise à jour de sécurité change de régime

Les **Extended Security Updates**, ou ESU, prolongent l’accès à certaines mises à jour de sécurité après la fin du support d’un produit. Leur traitement commercial pouvait donner une raison supplémentaire d’envisager Azure. Pour SQL Server 2014, par exemple, Microsoft rappelle que les clients utilisant des machines virtuelles Azure recevaient ces mises à jour sans coût supplémentaire, tandis que ceux sur site ou dans d’autres clouds les payaient. <sup><a href="#source-9">[9]</a></sup>

Le 27 mars 2026, Microsoft a annoncé un prix catalogue identique selon le lieu de déploiement et le canal d’achat pour les nouvelles offres ESU lancées à partir du 1er avril 2026. Le texte exclut explicitement les offres existantes, dont Windows Server 2012, Windows 10 version 22H2 et SQL Server 2014. L’annonce d’avril sur SQL Server 2016 confirme l’alignement d’Azure sur les autres environnements. <sup><a href="#source-12">[12]</a></sup> <sup><a href="#source-9">[9]</a></sup>

Voilà une modification concrète de l’arbitrage : pour les nouvelles offres concernées, cet élément du prix catalogue cesse de varier avec la destination. Les coûts d’infrastructure, les remises négociées et les droits de déploiement conservent leurs règles propres. Un budget de migration doit donc dater ses hypothèses et identifier les versions concernées. Reprendre une ancienne comparaison vantant systématiquement les ESU gratuits sur Azure fausserait l’analyse des nouvelles offres.

## Deux procédures encore ouvertes

Le 31 mars 2026, la CMA décrivait des mesures prises ou annoncées sur les sorties de données et l’interopérabilité, dont les effets sur le choix restaient à apprécier. Elle constatait séparément une absence de progrès substantiel sur ses préoccupations liées aux licences. Ce diagnostic précédait l’enquête sur l’écosystème de logiciels d’entreprise de Microsoft, ouverte le 14 mai. Celle-ci doit déterminer si Microsoft devrait se voir attribuer un « statut de marché stratégique », ou SMS, pour cet écosystème. Au 9 octobre 2026, la page officielle consultée indique toujours une procédure ouverte. Son calendrier prévoit une proposition de décision en octobre, puis une décision finale au plus tard le 13 février 2027. Ce calendrier ne vaut pas publication d’une décision. <sup><a href="#source-13">[13]</a></sup> <sup><a href="#source-15">[15]</a></sup>

Dans l’Union européenne, la Commission a communiqué le 25 juin 2026 sa position préliminaire selon laquelle Amazon et Microsoft devraient être désignés contrôleurs d’accès au titre du Digital Markets Act pour leurs services AWS et Azure. Elle évoque notamment les coûts de changement et les effets de leurs écosystèmes. Cette étape porte sur le rôle des plateformes cloud ; elle demeure distincte d’un jugement sur une clause particulière de licence. <sup><a href="#source-16">[16]</a></sup>

Ces démarches éclairent aussi la différence entre concurrence et souveraineté. Faciliter le passage d’Azure à AWS ou Google peut renforcer la compétition entre ces fournisseurs. Développer une offre européenne capable d’accueillir le même logiciel répond à une autre dimension du choix. Enfin, pouvoir maintenir ou remplacer le logiciel lui-même engage des capacités différentes. Le mot « sortie » mérite donc toujours une destination précise.

## Choisir qui pourra faire fonctionner le service demain

Pour une administration, le dossier d’achat gagne à décrire un trajet concret : ce service, avec ces versions et ces licences, doit pouvoir fonctionner chez cet autre hébergeur. À partir de là, les équipes peuvent demander les conditions applicables, identifier les droits à maintenir et comparer des offres réellement accessibles. L’exercice rapproche les juristes, les acheteurs et les responsables techniques autour du même scénario.

La sécurité de l’hébergement appelle son propre examen. L’ANSSI explique que SecNumCloud évalue notamment l’autonomie d’exploitation et la protection vis-à-vis des lois extra-européennes. Son référentiel est conçu sans présupposer les technologies utilisées. L’agence précise aussi que la qualification d’une offre cloud ne préjuge pas du niveau de sécurité d’un service numérique qu’un client y héberge. Le périmètre qualifié et les droits sur les logiciels apportés doivent donc être établis séparément. <sup><a href="#source-17">[17]</a></sup>

Ce troisième volet fait apparaître une dépendance située entre le logiciel et le bâtiment qui l’abrite. L’application peut être techniquement transportable et sa destination modifier les licences nécessaires. À l’inverse, un droit de déploiement plus large peut ouvrir des choix d’hébergement tout en laissant à l’équipe le travail de migration.

La [réversibilité](/glossaire/reversibilite/) se prépare en reliant ces deux réalités. **Une alternative devient exploitable lorsque l’on sait à la fois la faire fonctionner et exercer les droits qui permettent de l’utiliser.** C’est ce lien qui donne une portée opérationnelle au choix souverain de l’acheteur.
